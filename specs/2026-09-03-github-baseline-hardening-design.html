1. 目标

保留 Claude 已写出的 11 章和 6 张提示词卡，但把它们统一定位为未验证的草稿种子，不算完成课程。先把 GitHub 仓库变成可信的后续开发基线，再按模块逐条核实和完善正文。

2. 已确认的现状

  • src/content/、src/chapters.json 和 src/build.py 已形成可保留的源码生成体系。
  • 根目录是在线阅读生成物；downloads/ 是离线发行物；两者当前共用了不适合离线包的清单。
  • 根站页面与锚点目前可访问，但离线 ZIP 的首页链接和包内 manifest/checksum 不闭合。
  • src/check.py 在 Windows 默认 GBK 输出下会失败，也没有真正证明源码与生成物同步。
  • 公开仓库的状态文字同时出现“11/11 正文完成”和“框架审核、种子不算完成课程”，需要统一。
  • v0.2.2 是未合并的验证准备分支；本设计不直接合并它。

3. 方案选择

采用“保留草稿、先修工程基线”的方案。既不回退到最初 15 文件框架，也不把 0.2.1 当成已完成课程。

  1. 源码：src/ 是编辑入口。
  2. 在线产物：根目录 HTML/CSS 是由源码生成的公开预览。
  3. 离线产物：在独立暂存树中生成，只包含包内真实存在的文件，并拥有自己的 manifest/checksum。
  4. 状态：11 章和 6 张提示词卡都标记为 draft seed / unverified；不得写成完成课程。
  5. GitHub：所有改变通过功能分支和 Pull Request；main 不直接提交。

4. 本次实现范围

4.1 跨平台确定性构建

  • 所有文本生成固定 UTF-8、LF 和末尾换行。
  • 保留固定 ZIP 条目顺序、时间戳和权限。
  • README 中跨页链接宏展示为真正的双花括号语法。
  • 在 Windows 与 Linux CI 上分别运行构建一致性检查。

4.2 离线包闭环

  • 离线首页不再链接包内不存在的 ZIP 下载文件。
  • 离线 manifest 和 SHA256SUMS 只列出实际进入 ZIP 的文件。
  • ZIP 外生成独立 SHA-256 文件，便于下载后核对。
  • 检查器必须解包验证：路径安全、文件集合、大小、哈希和本地链接。

4.3 真实发布门禁

  • check.py 使用 ASCII 状态前缀，不能因 Windows 控制台编码崩溃。
  • 递归检查全部公开 HTML，而不只检查根目录页面。
  • 缺少登记表 schema 校验能力时，严格模式必须失败，不能显示“全部通过”。
  • 新增无写入的构建同步检查：在临时目录重建并与提交产物逐字节比较。
  • GitHub Actions 在 Windows 与 Linux 上执行严格检查。

4.4 状态与文案收敛

  • README、首页、登记表统一写成“11 章均有草稿种子，尚未逐条复核或实测”。
  • 保留 currentSeedContent.final=false 和“不计作完成课程”。
  • 在线部署配置保留为可选预览能力，不作为教程主要载体或当前完成门槛。
  • 框架版本、内容版本和发行物版本分开表达，避免把框架 1.0.0 覆盖成内容 0.2.1。

5. 不在本次范围

  • 不逐章修订课程正文，不把任何模块改为 verified。
  • 不执行安装、登录、插件授权、Skill 安装、定时任务或第三方账号测试。
  • 不启用 GitHub Pages，不部署服务器。
  • 不决定开源许可证；该选择需要用户单独确认。
  • 不重写 Git 历史、不删除 v0.2.2 分支；其中路径信息的清理需要单独授权。
  • 不在本 PR 建完整的逐模块内容目录；它是下一阶段独立 PR。

7. 验收标准

  1. Windows 和 Linux 的 CI 均能重建出一致的文本与离线文件集合。
  2. 离线 ZIP 解压后全部本地链接有效，manifest/checksum 无缺失或额外文件。
  3. ZIP 外部 SHA-256 与实际 ZIP 一致。
  4. 在没有严格 schema 校验条件时，发布检查明确失败。
  5. 修改任一源码片段但不重建时，检查器能够发现生成物过期。
  6. 公开页面只称“草稿种子”，不声称课程已完成或平台已验证。
  7. PR 不包含真实账号、证据截图、本机绝对路径或未清理的维护会话记录。
