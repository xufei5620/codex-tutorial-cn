第 7 章 草稿

Skill

  • 预计阅读 9 分钟
  • 适用平台：Windows / macOS（步骤相同）
  • 前提：读过第 4、5 章；读过第 6 章会更容易理解 Skill 与插件的区别
本章目标

理解 Skill 是什么、它和插件有什么不同；会在对话里调用一个 Skill；会用 Codex 自带的「Skill 制作器」做一个属于自己的 Skill；知道怎么更新、停用和删除它。

7.1Skill 是什么：让 Codex 按固定流程做事

第 4 章教你每次把「任务・范围・材料・期望」写清楚。用久了你会发现，有些事每周都要做一遍，每次都得重新打一遍同样的要求——比如「把这周的流水整理成周报，格式是……，注意……」。

Skill（技能）就是把这套要求写成一份固定的说明书，存在电脑里。以后只要一句「用周报技能处理这份流水」，Codex 就会自己去读那份说明书，照着做。还是「新同事」的比喻：Skill 是你写给他的一页操作手册，写一次，以后每次照办。

从电脑的角度看，一个 Skill 就是一个文件夹，里面必有一个叫 SKILL.md 的文本文件（写着这个技能叫什么、什么时候用、具体怎么做），可能还有一些参考资料或小程序。这套格式是一个公开标准（叫 Agent Skills），不是 Codex 独有的。

Codex 自带几个官方 Skill，其中两个你会在本章用到：skill-creator（帮你做新 Skill 的 Skill）和 skill-installer（帮你安装别人做的 Skill）。

7.2Skill 和插件的区别

Skill插件（第 6 章）
本质一份「怎么做事」的说明书一个安装包，里面可能有说明书，也可能有连接外部账号的「钥匙」
需要连接账号吗不需要大多需要
存在哪里你自己电脑上的一个文件夹由应用统一管理
主要风险说明书里可能带「小程序」，会在你电脑上运行——所以要看来源交出去的账号权限
适合谁做你自己就能做（7.5）通常是开发者或公司做

一句话：Skill 是说明书，插件是说明书加钥匙。插件里往往打包了好几个 Skill；反过来，一个 Skill 也可以单独存在、不属于任何插件。

7.3安装前的检查：来源、它会执行什么

Skill 不需要交钥匙，听起来很安全。但它有一个自己的风险点：说明书里可以附带脚本（小程序），Codex 执行技能时可能会运行它们。一段脚本能做的事，和你在电脑上手动能做的事一样多——包括删文件。所以来源不明的 Skill 和来源不明的软件一样，不能随便装。

三条检查规则：

  1. 只装两种来源：官方提供的（Codex 自带、或 OpenAI 官方目录里的），以及你自己用 7.5 的方法做的。网上别人分享的 Skill，零基础阶段一律不装——哪怕看起来很实用。
  2. 装之前把 SKILL.md 读一遍。它是普通文本，双击就能打开。读不懂没关系，只看一点：里面有没有提到「运行脚本」「执行命令」「删除」之类的词。有的话，不装。
  3. 留意应用给的标记。通过应用上传或安装的技能会被自动扫描，标成 Available（可用）、Needs Review（需要复核）或 Blocked（已拦截）。后两种不要碰。官方也说了，扫描「不能代替你自己的检查」。

你自己的 Skill 默认存在你的个人文件夹下一个叫 .agents/skills 的文件夹里（名字以点开头，系统默认把它隐藏起来，这是正常的）。旧版文档写的是 .codex/skills，如果你在别处看到这个说法，指的是同一类东西。你不需要手动去找它——用 7.5 的方法创建时 Codex 会自己放好。

7.4怎么调用一个 Skill

  • 输入 $。在 Codex 的输入框里打一个美元符号，会弹出已安装 Skill 的菜单，用鼠标或方向键选一个，再接着写你的要求。也可以直接打全名，比如 $skill-creator。
  • 查看有哪些。输入 /skills 并发送，Codex 会列出当前可用的技能。
  • 让它自己挑。不点名也行：每个 Skill 的说明书里写了「什么时候用」，Codex 会根据你的请求自动判断该不该用某个技能。新手建议还是点名，更可控。

在 Codex 视图里点名技能用 $；如果你切到 Chat 或 Work 视图，同样的事用 @。记不住也没关系，打错了 Codex 通常会提示。

7.5动手：做一个自己的 Skill

不用写任何代码——Codex 自带的 skill-creator 会像面试一样问你几个问题，然后替你把说明书写好、放到正确的位置。下面用蓝溪文具（虚构）的「周报」做例子。

  1. 先想清楚三件事。这个技能叫什么（周报整理）；什么时候用（每周把销售流水整理成周报）；固定要求是什么（分「本周销售」「异常情况」「下周待办」三部分；只用流水里有的数字；异常情况要写出依据）。这就是第 4 章的四要素，只是要写成「每次都适用」的形式。
  2. 新开一个对话，发出创建请求。

$skill-creator 帮我做一个 Skill，名字叫「周报整理」。 用途：把我贴进来的一周销售流水整理成周报。 什么时候用：当我说「整理周报」或贴入一周的流水并要求周报时。 固定要求：①分三部分——本周销售、异常情况、下周待办；②只使用流水里出现的数字，不要估算或补充；③「异常情况」每一条都要写出判断依据；④总长不超过 300 字。 不需要任何脚本，纯说明书就好。

  1. 回答它的追问。skill-creator 通常会确认用途、触发时机，并问要不要附带脚本——回答不要。做完后它会告诉你技能已创建、放在哪个文件夹。
  2. 试用一次。新开一个对话，输入 $，菜单里应该出现「周报整理」。选中它，贴一段虚构流水：

$周报整理 材料：9/1 樱花笔记本 32 本、荧光笔 18 套；9/2 樱花笔记本 41 本、荧光笔 9 套；9/3 樱花笔记本 12 本（下午停电两小时）、荧光笔 20 套；9/4 樱花笔记本 38 本、荧光笔 15 套；9/5 樱花笔记本 40 本、荧光笔 17 套、钢笔套装 3 套。

  1. 按第 5 章的三分法检查。数字是不是流水里的；「异常情况」有没有写依据（比如「9/3 樱花笔记本仅 12 本，流水注明当天停电两小时」）；有没有多出流水里没有的东西。不满意就回到第 3 步的对话，让 skill-creator 修改说明书，而不是每次用的时候临时补要求。

预期结果：以后每周只要 $周报整理 加一段流水，就能得到格式一致的周报。你写清楚一次，它照办无数次。

做 Skill 时不要把真实的客户名单、供应商联系方式、内部价格表写进说明书。说明书是一个存在电脑里的文本文件，会在每次调用时被读取、发送到服务器。它应该只写「怎么做」，不写「具体的敏感数据」——数据每次用的时候再作为材料提供。

7.6更新、停用与移除

要做什么怎么做
修改要求最省事：新开对话，$skill-creator 把「周报整理」的字数上限改成 400 字。它会替你改说明书。也可以自己用记事本打开 SKILL.md 直接改，保存后 Codex 会自动重新读取（偶尔需要重启应用）。
暂时不用官方提供的方法是在一个设置文件里把它标为停用，这一步涉及编辑配置文件，零基础读者可以跳过——不点名调用，它就不会主动干扰你。
彻底删除把它的文件夹从 .agents/skills 里删掉（官方没有专门写删除步骤，这是按「Skill 就是一个文件夹」推断的做法；删除前先把整个文件夹复制到别处备份——第 5 章的习惯）。也可以直接对 Codex 说「帮我删除周报整理这个 Skill 的文件夹」，然后在审批弹窗里核对它要删的路径确实是那个文件夹，再点允许。
安装官方目录里的 Skill$skill-installer 加上技能名称，比如 $skill-installer pdf；装完通常要重启应用。只装官方目录里的（见 7.3）。

本章小结

  • Skill 是一份固定的说明书，写一次、以后每次照办；本质是电脑里的一个文件夹加一个 SKILL.md。
  • Skill 是说明书，插件是说明书加钥匙。Skill 的风险点是可能附带脚本，所以只装官方的和自己做的。
  • 调用：输入 $ 选技能；/skills 查看清单。
  • 用 $skill-creator 对话式地做自己的 Skill；说明书只写「怎么做」，不写敏感数据。
  • 改要求让 skill-creator 改；删除前备份文件夹。
