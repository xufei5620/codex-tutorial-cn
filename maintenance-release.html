逐条补课与发布

框架先稳定，课程以后逐条补。每个模块独立通过同一条生命周期，避免“目录看起来完整、正文其实未验证”。

发布原则：先完成一个可审计模块，再扩展下一个。没有通过对应发布门禁的内容，不能因为章节目录已有位置就被当作已完成课程。

单条课程的状态机

outline → draft → source-and-rights-review → editorial-reviewed → verification → acceptance-ready → stable → retired

状态完成条件不允许的捷径
outline确定模块 ID、读者目标、边界、前提、来源候选和验证计划。不能把目录标题当作教学内容。
draft完成可离线阅读的 HTML：步骤、预期、风险、检查、修正、来源和版本信息齐全。不能用“待补图”“以后验证”代替必需内容。
source-and-rights-review逐条确认事实来源、引用范围、许可证、示例归属与公开权利。章级来源清单不能自动替代单元级复核。
editorial-reviewed另一次检查确认新手能理解、术语被解释、步骤与安全停止点完整。作者自评不等于审阅，也不能冒充平台实测。
verification按声明的平台和产品版本执行可控步骤，记录实际结果、证据与限制。官方文档、截图或另一平台的成功不能替代声明的平台证据。
acceptance-ready内容、来源、权利、安全、可访问性、构建与发行清单均达到候选门槛。不能跳过清单或手改构建产物。
stable所需人工验收完成，必经路径的验证证据有效，正式发行物已冻结。Beta、草稿或仅单平台结果不能标为稳定版。
retired内容已撤下并保留原因、影响范围、替代项和必要墓碑记录。不能静默删除已发布身份或复用旧 ID。

单人维护时 editorial-reviewed 的替代规则

没有第二位审阅人时，按以下方式满足"另一次检查"，并在模块的维护者信息中留下记录（日期 + 采用的方式）：

  • 冷却复查：草稿完成后至少间隔 24 小时，以读者视角按固定清单逐项重读：新手能否照做、术语是否都解释过、链接/许可/隐私边界是否正确、有没有未验证的断言。
  • 辅助审阅：可用 AI 辅助按同一清单出具审阅意见，但采纳与否由维护者人工判断并记录；辅助审阅不能替代冷却复查，只能叠加。

每条课程的固定交付包

  • 语义 HTML 正文及永久模块 ID。
  • 明确的目标、前提、步骤、预期结果、检查方法、一次修正闭环和风险提醒。
  • 来源、固定版本/日期、许可证与使用方式；自有示例与第三方素材分开登记。
  • 模块 × 平台 × 浏览器 × 产品/扩展版本的验证记录，以及六种公开验证状态之一。
  • 若涉及插件或 Skill：安装、权限/数据、基础使用、更新、停用/移除和残留检查。

版本、过期与复验

稳定版本采用 YYYY.MM.N，对应不可变标签 vYYYY.MM.N；RC 仅使用内部编号，不占用稳定版本。构建 ZIP、校验值和发行清单一经发布不回写，修改必须形成新版本。

风险级别最晚复验提前过期事件
高30 天权限、费用、删除、外部发送、安全行为或核心步骤改变
中90 天产品界面、功能、依赖、许可证或关键来源改变
低180 天可复现反馈、链接失效或资料出现矛盾

过期并不等于错误，但必须显示 verification-expired，并暂停受影响的核心路径；更新前先查依赖图，只复验被影响的模块与代表读者路径。

安全例外、撤回与备份

发现密钥、个人隐私、侵权素材或恶意载荷时，立即停止下载、推荐、公开 Notion 和未来 GitHub 分发。不得用同版本偷偷换包。保留版本号、旧校验值、发现时间、原因、处理记录和必要哈希作为墓碑；危险字节不再分发，修复后另发热修版本。

维护前先制作可恢复备份并记录其位置、来源版本和校验值；备份只能用于恢复，不得成为未审查内容重新流入公开产物的渠道。恢复后仍需重新构建和验证。

开发仓库与正式发布

开发与发布是两回事。用于备份和日常开发的远程 Git 仓库（即本项目当前所在的仓库）随时可用，不受验收限制。面向读者的正式发布——打版本标签、发 Release、部署到服务器——须在用户验收后进行，且只发布通过公开白名单审查的内容：读者 HTML、必要自有资产、许可和发行资料。原始反馈、详细环境日志、未清权素材、秘密和内部审核材料绝不进入发布内容。

进度追踪：以 Git 登记表为准

当前阶段不启用 Notion 台账。章节导航以 src/chapters.json 为准；65 个课程模块与现有提示词卡的身份、内容状态、验证状态和证据字段以 src/modules-v1.json 为准，构建后公开为 registry/modules-v1.json。Notion 工作流（见 notion-workflow.html）只保留为未来多人协作时的单向投影方案。
