Notion 协作工作流

Notion 是私有维护控制台，不是教程的第二个权威源。它帮助收集素材、反馈和复验任务；真正可发布的内容只能从 Git 中生成。

状态：当前阶段暂缓启用（2026-09-01 决定）。单人维护阶段不建 Notion 台账：章节导航以 src/chapters.json 为准，内容单元身份与双状态以 src/modules-v1.json 为准，并构建为公开只读的 registry/modules-v1.json。本页保留为未来多人协作时的启用方案；届时仍不得维护第二套事实源。
边界：本框架不要求读者拥有 Notion，也不把私有反馈、原始截图、环境日志或未清权素材同步到公开页面。公开 Notion 仅在用户验收后，作为 Git 已发布版本的单向可读投影；可以上传或嵌入图片，但必须保留媒体 ID、GitHub 源路径和最后复核日期；界面截图还必须保留实际截取日期 captureDate，它不等于最后复核日期，Notion 上的任何编辑都不能回写课程源文件。

一条事实如何流动

素材或反馈 → 私有 Notion 登记 → 核实来源与风险 → 在 Git 编辑课程模块 → 本地构建与验证 → 用户验收 → 公开白名单投影（可选）

任何一个环节发现事实尚未核实、来源不清、含个人信息或不适合公开，都停在私有层处理；不能通过 Notion 页面“先发布再补证据”。

建议的私有数据库

数据库用途最小字段
课程模块投影每一个已登记内容单元；不在 Notion 新建正式身份。永久单元 ID、标题、所属章节、内容状态、验证状态、公开路径、平台、风险、最近复核日期
素材与来源登记官方文档、GitHub 项目、图片、提示词方法和授权条件。来源名称、URL、固定版本或 commit、许可证、使用方式、审查结论、权利状态、登记日期
图片与效果图登记维护者上传、嵌入或复核过的图片投影；不把 Notion 当作图片的权威源。媒体 ID、行业、Prompt ID、图片 URL 或附件、来源、权利状态、验证状态、GitHub 路径、最后复核日期；界面截图另含实际截取日期 captureDate
反馈收集读者问题，避免把原始隐私信息写入课程。教程版本、模块 ID、问题描述、平台、产品版本、脱敏附件、处理状态、关联任务
复验与发布任务管理“谁在什么环境复验了什么”。任务 ID、模块 ID、环境、步骤、预期、实际、证据位置、验证状态、到期日、阻断级别
变更与撤回保留发行决策、风险和墓碑记录。版本、影响模块、变更类型、风险级别、决定、发布日期、撤回原因、替代版本

内容状态与 Git 的关系

Notion 的看板只显示工作状态；Git 中的 HTML、src/modules-v1.json、测试和发行清单才是可复现的事实。内容生产状态与产品验证状态必须作为两个字段投影，不能由看板列名互相推导或自动提升。

Notion 中的草稿不能视为课程，公开投影也不能反向覆盖 Git。每条卡片只链接永久单元 ID 与公开路径，不复制一份正文；需要修改时回到 Git，经构建生成新的 registry/modules-v1.json。图片和效果图也遵守同样的单向规则：Notion 可以展示投影，但图片登记的权威仍在仓库里的 src/media-v1.json 和维护者文档里，构建时只把已登记的图片复制到 assets/media/，并由 manifest.json、SHA256SUMS.txt 和离线 ZIP 继续覆盖发布结果。

公开投影的单向门禁

  1. 在 Git 中完成课程条目、来源/许可登记和所需验证。
  2. 构建本地 Notion 投影预览，检查标题、正文、链接、模块 ID 和版本是否一致。
  3. 用户验收该候选版本；验收前不建立公开 Notion 页面。
  4. 仅从公开白名单生成隐藏的新版本页面树；不手工复制私有库内容。
  5. 完整检查后原子切换“当前推荐版本”；旧公开版保留其版本标识或按撤回规则处理。

公开投影不回写 Git，不接受在公开 Notion 直接改正文。发现差异时，以 Git 修正并重新生成投影。

图片投影与止损条件

图片台账的入口是仓库里的 src/media-v1.json；构建器只会把已登记且通过校验的图片复制到 assets/media/，并把它们纳入 manifest.json、SHA256SUMS.txt 和离线 ZIP，不会生成额外的图片 registry 页面。每条记录都要把媒体 ID、行业、Prompt ID、图片 URL 或附件、来源、权利状态、验证状态、GitHub 路径和最后复核日期写全；界面截图还必须写实际截取日期 captureDate，不能用 lastReviewedDate 代替。Notion 里可以上传或嵌入图片，但必须保留原始媒体 ID 和 GitHub 源路径，方便回指和复验。

  • 权利状态是 pending、来源不明、许可冲突、路径缺失或无法写清 GitHub 源路径时，立即停用公开投影。
  • 图片一旦改成生成示例，就必须保留 generated-example 标记，不得伪装成现场截图、官方图或真实拍摄。
  • Notion 的编辑只允许调整展示顺序、说明文字和复核状态，不得把图片投影写成新的课程来源。

反馈处理的最小闭环

读者反馈只需提供教程版本、模块 ID 和问题描述。处理人先脱敏，再判断它是内容错误、平台差异、失效来源、可访问性问题还是新需求；随后创建关联维护任务。可复现的问题要写入 Git 修复和验证记录，不能只在 Notion 卡片里标“已解决”。
