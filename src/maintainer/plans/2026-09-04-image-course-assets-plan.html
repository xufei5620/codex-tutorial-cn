图文课程资产系统实施计划

Goal：在不破坏现有 HTML-first 教程、离线 ZIP、GitHub 和 ChatGPT Sites 的前提下，加入可追溯、可访问、可维护的图片资产管线，并先为第 1–5 章放入两张自有概念图。

Architecture：以 src/media-v1.json 作为图片资产登记表，以 data-media-id 和 {{media:...}} 将正文与资产绑定；构建器解析媒体宏、复制本地资产、更新 manifest/SHA256/ZIP，检查器拒绝未登记、无版权状态、缺少 alt 或远程图片。界面截图、示意图和行业 Prompt 效果图分开管理，Notion 只做投影，Sites 使用同一份生成静态目录。

Tech Stack：现有 Python 标准库构建器与检查器、JSON Schema、语义化 HTML、SVG/PNG/WebP 静态资源；不新增 JavaScript、数据库、上传服务或运行时依赖。

Spec：src/maintainer/specs/2026-09-04-image-course-assets-design.html

全局约束

  • 源图片只放 src/media/；生成图片只出现在 assets/media/，不手改根目录生成页面。
  • 图片 ID 使用 IMG-<用途>-<四位序号>，例如 IMG-C01-0001 和 IMG-PROMPT-0001；同一 ID 不得重复。
  • 所有正文图片使用相对路径；禁止远程图片 URL、数据中含凭据的图片和路径越界。
  • 每张图必须有非空 alt、图注、rights、sourceType 和 verificationState；版权或来源不清时不得发布。rights=pending 只能留在源登记表，不能被正文宏、公开目录、manifest、校验和或离线 ZIP 使用。
  • 界面截图只有在记录平台、应用版本、captureDate 截取日期并保留 unverified 时才能进入实测前版本；示意图必须写明“示意图”或“生成示例”。
  • 媒体文件后缀必须与 mediaType 一致；效果图的 promptId 必须解析到 src/modules-v1.json 中真实存在的提示词卡，未解析的占位 ID 不得发布。
  • 没有图片时，现有 0.4.0 正文、链接、manifest、ZIP 和 Sites 内容保持字节级兼容；新增图片后在线、离线和 Sites 的相对路径一致。
  • 所有图片都必须进入公开白名单；不提交真实客户资料、密码、验证码、API Key、私人路径或未经授权的 GitHub 素材。
