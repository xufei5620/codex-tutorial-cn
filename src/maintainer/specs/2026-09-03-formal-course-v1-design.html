Codex 中文正式课程 V1 设计

状态：用户已确认继续；实施按 GitHub 分支和 Pull Request 进行。

设计日期：2026-09-03。

1. 成果定义

把现有 11 章正文和提示词库从“完整草稿”推进为可长期维护、可公开学习、证据状态诚实的正式课程。课程继续面向第一次接触 AI 与 Codex、没有编程或命令行基础的中文读者。

正式课程分成两个明确阶段：

  1. 1.0 Beta：全部必需正文、示例、来源、权利、安全、离线阅读和无障碍审校完成；尚未实测的产品操作仍明确标注 unverified。
  2. 1.0 Stable：Beta 的关键操作路径在 Windows 和 macOS 真实环境完成验证，失败或过期项已经修订、隔离或移除。

2. 内容范围

V1 保留 11 章主结构：导读、AI 与 Codex、安装与界面、基础对话、日常协作、插件、Skill、常见任务、完整案例、排错、安全与参考维护。行业提示词库继续作为独立入口，不作为第 12 章。

Claude 已写出的 11 章和 6 张通用提示词卡全部保留为 draft seed。它们是正式课程的输入，不自动获得“已完成”或“已验证”状态。

软件开发、CLI、IDE、API、SDK、Git 教学与 Linux 操作不进入 V1 主课程。Skill/插件开发只保留概念入口，不作为零基础必修路径。

3. 内容单元与状态

章节只是导航容器；可审校和可发布的最小单位是课程模块或提示词卡。每个单元必须拥有稳定 ID、标题、章节、平台、风险、来源、权利、验证状态和最近复核日期。

内容生产状态统一为：

outline → draft → source-and-rights-review → editorial-reviewed → verification → acceptance-ready → stable → retired

产品验证状态只使用：

verified / verified-with-limitations / verification-failed / unverified / unsupported / verification-expired

内容生产状态与产品验证状态不得互相替代。Beta 可以包含清楚标注的 unverified 操作模块；Stable 的必经路径不可以。

4. 课程质量合同

每个操作模块至少包含：目标、适用条件、准备材料、步骤、预期结果、风险与停止条件、检查方法、一次受控修正、平台差异、来源和验证状态。

每个事实性产品断言必须链接到具体官方来源并记录查阅日期。易变界面、套餐、权限、安装和扩展行为还必须记录适用平台与版本；没有证据时使用条件措辞，不猜按钮名称。

所有案例只使用虚构数据或明确可再分发材料。读者不需要访问 GitHub 才能完成课程。外部发送、授权、支付、发布、删除、真实账号和个人数据操作必须设置停止点。

5. 技术与发行架构

  1. src/ 是课程源码与维护数据入口。
  2. 在线预览是源码生成物；它不是第二份可手改正文。
  3. 离线 ZIP 在独立暂存树中生成，拥有与实际文件集合一致的 manifest 和 SHA256SUMS。
  4. 读者端无 JavaScript、无远程运行资源、无账号、无追踪；主动点击官方来源链接可以联网。
  5. GitHub 是开发协作和版本权威；所有改动走分支、检查和 PR。
  6. GitHub Pages 与服务器部署保持可选，不是课程正式化的必要条件。
  7. Notion 只作为私有维护台账和未来只读投影，不是内容权威。

6. GitHub 开发阶段

  1. 阶段 A：工程基线。修复跨平台构建、离线包、严格检查、状态表述和 CI。
  2. 阶段 B：模块目录。把现有章内小节登记为稳定模块，统一生命周期、来源和验证字段。
  3. 阶段 C：基础篇审校。完成第 1–5 章的来源、语言、示例和安全审校。
  4. 阶段 D：扩展篇审校。完成插件与 Skill，删除未经证实的固定界面行为。
  5. 阶段 E：场景、案例与提示词库。完善第 8–9 章、26 张行业卡和合法效果资源。
  6. 阶段 F：排错、参考与 Beta。完成第 10–11 章、全站无障碍、离线包和 1.0 Beta。
  7. 阶段 G：真实设备验证。用户参与 Windows/macOS 高风险步骤，形成 1.0 Stable。

每个阶段使用独立 PR。PR #2 只承担阶段 A，避免把工程重构和大规模正文修订混在一起。

7. Beta 验收门槛

  • 11 章均无占位、无内部矛盾、无未解释必需术语。
  • 每个公开单元具有来源、权利、风险、状态和平台记录。
  • 所有演示输入和结果均为虚构/自有/已清权；提示词卡有真实可打开结果。
  • 公开 HTML、离线 ZIP、manifest、checksum、链接、搜索、键盘路径、缩放和打印检查通过。
  • 所有未实测操作在正文与维护记录中同时标记 unverified，不以 Beta 名义伪装验证。
  • 公开仓库和发行物不含秘密、个人信息、本机绝对路径或内部会话记录。

8. Stable 验收门槛

  • Windows 与 macOS 必经路径分别拥有环境、版本、日期、观察结果和证据。
  • 安装、登录、权限、文件修改、插件、Skill、完整案例和排错路径不存在失败、过期或未验证的必需项。
  • 只有不影响关键学习结果和安全边界的限制，才允许标记 verified-with-limitations。
  • 用户批准最终候选后再创建稳定标签和不可变发行包。

9. 用户参与边界

编辑审校、构建、链接、许可、虚构案例和自动化检查由维护代理完成。登录、身份、验证码、第三方授权、付费、真实发送、真实发布以及需要读取实际界面的高风险步骤由用户操作或明确授权；代理不得推断结果。
