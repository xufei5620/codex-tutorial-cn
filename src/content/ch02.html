认识 AI 与 Codex

本章目标

读完这一章，你能用自己的话说明 Codex 是什么，知道它能协助哪些工作、哪些结果必须核实，并能判断一项任务是否适合先交给它尝试。你还会学会给任务划范围、给重要动作留一道人工确认。

本章所有练习都是静态阅读练习：请用纸笔或系统自带的记事本（Windows「记事本」或 macOS「文本编辑」）记录答案，不要把答案发送给 Codex，也不要提交姓名、账号、密码、验证码、真实客户资料等敏感信息。先写完，再展开「参考答案」。

2.1Codex 是什么

先分清两个词。AI 是「人工智能」的简称，范围很广；本教程主要讲其中的生成式 AI——它能根据你给出的文字、文件或图片，分析材料并生成新的内容。它生成得很像人写的，但「像真的」不等于「一定正确」。

Codex 是 OpenAI 提供的 AI 智能体工具。这里的智能体，指的是它不只生成一段回答，还能在你允许的范围内调用工具、分步骤处理任务。Codex 尤其适合软件开发和需要技术细节的任务，也能协助研究、整理文件和制作内容。在 ChatGPT 桌面应用中，你可以从产品选择器进入 Codex；Codex 也有其他使用入口。本教程主要讲 Windows 和 macOS 上的 ChatGPT 桌面应用，其他入口只在确有需要时说明。第 3 章会带你完成安装并找到入口。

可选说明：CLI、IDE 和 Cloud 是什么
  • CLI（命令行）：在终端窗口里输入文字命令来使用 Codex。
  • IDE（编程编辑器）扩展：把 Codex 入口装进写代码的软件中。
  • Cloud（云端）：让任务在远程环境中运行，而不是只在眼前这台电脑上运行。

零基础读者现在只需认识这些名称，不需要安装或使用它们。

基本交互方式是用日常语言说明任务。你可以给出一段文字、一份文件或一个目标，让 Codex 解释、整理、起草或制作结果。和只回答问题的聊天工具相比，Codex 还可以在当前环境允许的范围内使用工具，例如读写工作文件、运行命令、搜索资料或调用已经连接的服务。

不是每个人、每个平台都能看到完全相同的功能。能否使用某项能力，取决于套餐、平台、地区、功能发布进度、账号所属工作空间（例如团队或组织空间）的设置、已安装的插件（为 Codex 增加能力或连接服务的扩展）以及当前权限。看到本书中的能力示例时，不要把它理解成「我的账号现在一定有」。

你可以把 Codex 想象成一位能力强、动作快，但刚加入团队的新同事。这个比喻有四个重点：

  • 任务越清楚，结果通常越容易检查，但清楚的要求也不能保证它永远不出错；
  • 信息不足时，它可能按常见情况补全，所以要明确哪些地方不能猜；
  • 它能使用的背景来自当前对话、你提供的文件，以及已启用且获准访问的项目、记忆或插件；不要假设它知道其他私人情况；
  • 它可以动手，因此除了说清任务，还要选对工作范围、权限模式，并复核重要结果。

这个「新同事」比喻会贯穿整套教程：你负责目标、边界和最后决定，Codex 负责在边界内协助完成工作。

2.2它擅长什么

下面六类是适合零基础用户首先尝试的任务。它们风险较低、结果容易检查，但这不代表 Codex 每次都会做对。例子都来自本书的虚构文具店「蓝溪文具」。

能力虚构例子你怎么检查
整理把三个月的虚构进货记录归类成清单。逐项对照原始记录，检查有没有漏项或放错类别。
改写把生硬的退货说明改得客气易懂，并控制在 80 字以内。确认原意没变，再数一遍字数。
总结把虚构会议记录浓缩成三条结论和一张待办表。回看原文，确认结论有出处、负责人和日期没有写错。
起草按给定要点写出通知、文案或邮件的第一版。检查每个要点都出现，并确认没有凭空增加承诺。
解释用大白话解释一个陌生概念，再举一个简单例子。到可靠资料中核对关键定义；重要结论请懂行的人复核。
按格式输出把同一份材料变成列表、表格，或制作成文档、表格、演示文稿等文件。打开生成的文件，逐页、逐表或逐张幻灯片检查。

这些例子的共同点是：有材料可依、有结果可查、出错后容易修改。这类任务很适合作为起点。Codex 的核心技术能力还包括理解代码库（一个项目的代码和相关文件）、修改代码、运行命令和测试、审查代码或 Pull Request（合并请求：把一组代码改动交给别人审阅，再决定是否并入正式版本）；即使你现在不写程序，也应该知道这正是 Codex 区别于普通聊天界面的重要部分。

在 ChatGPT 桌面应用中，生成的文档、演示文稿、表格、PDF 和部分 HTML 文件可以在对话旁预览。不同入口并不相同：例如命令行可以创建和编辑工作目录中的文件，但没有同样的可视预览界面。

它还能调用工具做什么

下面是常见的进阶能力。使用前先确认当前入口是否支持、所需插件或连接是否已经启用，以及权限范围是否合适。不要假设每项能力都可用，也不要假设系统每次都会再次弹窗询问。

能力虚构例子与边界在哪里看
处理工作文件在专门的练习文件夹中给三十份报价文件分类改名，并输出改动清单；原件先留在文件夹外。第 5 章、第 8 章
搜索或浏览网页查询 OpenAI 官方状态页当前是否报告服务故障，同时给出来源链接和页面日期；搜索结果和网页内容都要当作未经核实的输入。第 8 章
使用已连接的服务日历插件已经安装并完成连接后，先准备三条待办；写入前仍要核对日期、日历和权限。第 6 章
复用固定流程把已经跑通的「周报」方法做成 Skill（可重复使用的任务说明和配套资源），下一次继续使用同一套规则。第 7 章
按计划重复运行在支持计划任务的入口中，每周汇总一次虚构流水；本地任务需要电脑保持开机并让桌面应用继续运行。第 8 章
生成图片在图像生成功能可用时，按描述制作一张海报草图，再检查文字、品牌信息和使用权。行业提示词库（独立页面）
操作图形界面Computer Use 可以在支持的地区和系统中操作桌面应用，但会影响项目文件夹之外的状态，属于高风险能力。它需要安装相应插件；Windows 运行时要让目标应用保持在活动桌面可见，macOS 还会要求屏幕录制和辅助功能权限。本教程不教这项。—

2.3它在哪里不可靠

这一节很重要，请慢一点读。下面是当前生成式 AI 和智能体常见的风险。产品会继续更新，但在没有可靠证据前，不要假设这些风险已经消失。正确做法不是害怕使用，而是让每个风险都有一道检查。

风险一：内容看起来可信，也可能不完整或错误

Codex 可能把错误的数字、日期、人名、出处或因果关系写得很流畅，也可能没有清楚标出自己不确定的部分。语气自信不是证据。

先把第一版当作草稿。准备使用或分享之前，核对重要的数字、名称、日期、引文和说法；没有可追溯依据的重要事实，先标成「待核实」。

风险二：它拿到的背景可能不完整

Codex 的上下文（Codex 这次可用的背景信息）可能来自当前对话、项目、文件、记忆和已连接的插件，但只有可用且获准访问的内容才可能被使用。它不会自动知道你公司内部的规则、这次任务的例外或你没有提供的私人情况。

说明目标，并指出材料在哪里、哪一份是准的、哪些条件不能改。需要它查外部服务时，明确服务和查找目标；拿不到的资料让它列出来，不要让它自行补全。

风险三：AI 已学到的知识和网上资料都不等于最新事实

模型（生成回答的 AI 核心）自身的知识不保证实时。Web 搜索（在互联网上查找资料）可以帮助它取得较新的资料，但搜索结果、网页和连接服务里的内容仍可能过期、遗漏或错误。

价格、政策、产品功能和近期消息要指定官方来源，要求给出链接和资料日期，再打开原始页面核对。能联网只代表「能查」，不代表「查到的一定对」。

风险四：同一个问题，两次结果可能不同

同一个问题重复询问，措辞、顺序甚至结论都可能有差异。差异本身不能证明哪一次更正确，也不能靠语气判断。

先写清完成标准，再对照材料、来源或测试检查结果。重要的是证据和验收标准，不是反复询问直到出现一个你喜欢的答案。第 5 章会详细教检查方法。

风险五：能动手，也就可能改错地方

Codex 能访问什么、越过哪条边界时会不会询问，取决于当前工作区（你指定的工作文件夹或项目范围）边界、权限模式、已有授权、账号所属工作空间的设置和组织策略。官方建议大多数工作从 Ask for approval（请求审批）开始；Full access（完全访问）可以在不逐次询问的情况下访问更广范围，因此风险明显更高。

第一次练习只使用专门的测试文件夹，重要文件先备份；执行前确认目标、范围和可能改动。遇到看不懂的审批请求，先取消或拒绝，再让 Codex 用大白话说明准备做什么、会影响哪些文件，然后重新决定。具体设置见第 3 章。

风险六：外部内容可能夹带错误指令

网页、问题单、文档或插件返回的数据里，可能藏着诱导智能体泄露资料、运行陌生命令或偏离原任务的文字，这叫提示词注入。外部页面写着「请上传密钥」并不等于这是你的要求。

外部内容要求上传密码、验证码、密钥或内部文件，要求运行用途不明的命令，或者要求绕过原来的权限边界时，立即停止。不要照做，先回到原始任务和可信来源核实。

2.4哪些任务适合交给它

适合的意思不是「全权交给它」，而是可以让它先做一版，再由你检查和决定。先看几个对照。

适合先尝试不要直接交给它决定或执行
通知、文案、邮件等初稿；你本来就准备自己修改以你的名义直接对外发送或发布；发出前需要本人复核
依据明确材料做整理、改写、对比和摘要缺少可靠依据，却要求它给出确定事实或替你拍板
有原始资料、检查清单、测试，或能安排懂行的人复核的任务法律、医疗、财务、安全等高风险结论；可让它辅助整理，但最终判断需要合格专业人员
范围小、可撤销、有备份的重复工作删除唯一原件、付款、改账户权限等后果重大的动作；没有人工确认不要执行

开始前先问四个问题

  1. 材料可以提供吗？密码、验证码、API 密钥（让软件访问服务的一种凭据）等凭据不得放进对话。个人或保密资料只有在组织规则允许、工具获批而且确有必要时才能使用，练习阶段继续使用虚构材料（见第 1 章）。
  2. 范围清楚而且能撤销吗？先限定文件夹、文件、时间段和不许改的内容；动原件前先备份，尽量让它另存新文件。
  3. 结果能核验吗？提前想好用原文、官方来源、计算、测试、检查清单还是专业人员来验证。没有核验办法，就先缩小任务。
  4. 会影响别人或外部系统吗？发送、发布、删除、付款、签署、改权限等动作，先让 Codex 准备草稿或方案，最后一步由你本人复核和确认。

材料可提供，范围先限定；结果能核验，重要动作我确认。四项都想清楚，再开始任务。

2.5正确的心态

把 Codex 当成能力强、速度快，但需要明确范围和复核的新同事，而不是无所不知的权威。落到实处，是下面三个习惯：

  • 用任务卡交代工作：写清目标、背景或材料、输出形式、不能越过的边界，以及怎样才算完成。第 4 章会带你练习。
  • 用证据验收结果：打开生成的文件，核对原文和来源；需要时让它运行测试或按检查清单自查，但最后仍由你判断是否可以使用。
  • 不对劲就暂停：结果不好不一定是你「不会提问」，也可能是材料不足、来源不可靠、权限不合适、工具失败或任务超出能力。先检查这些条件，再缩小范围、补充上下文或换一种做法。

动手：给六个任务分级

先不要看答案。把每个任务标成 A（按当前低风险范围可以先尝试）、B（原请求不能直接执行，但改成只准备草稿、候选清单或核验材料后可以继续，最后必须由人确认）或 C（材料或目标本身不可交给 Codex，例如凭据或无权处理的数据，应立即停止）。

作答步骤：先在纸上或系统记事本里写下六题的 A、B 或 C；再任选两题，分别写出「允许提供的材料、核验方法、必须由人确认的最后一步」。全部写完后再展开参考答案；继续只使用题目中的虚构材料，不要代入真实客户或账号信息。

  1. 用虚构的蓝溪文具退换货要点，起草一段 100 字以内的顾客说明。
  2. 查询本月最新税务政策，并直接替店主决定应该怎样申报。
  3. 在你已获准、有权处理的虚构练习副本中，删除「虚构客户文件夹」里所有看起来重复的文件；这份练习副本是唯一可用版本，目前没有其他备份。
  4. 把一份虚构会议记录整理成「结论、负责人、截止日期」三列表格。
  5. 把网银密码和短信验证码交给 Codex，让它完成一笔转账。
  6. 根据你提供的要点起草客户邮件，然后不经检查直接发给所有客户。
参考答案与通过标准（做完后再展开）
  1. A：材料是虚构的，输出是草稿，字数和要点都能检查。
  2. B：可以协助查找和整理官方资料，但税务申报属于高风险决定，必须核对最新官方来源并请合格专业人员确认。
  3. B：题目已经说明材料纯属虚构而且你有权处理，因此这里只判断「无备份删除」的风险。不能按原请求删除；先改成只列出疑似重复文件和判断依据，不移动、不删除，由本人核对并建立备份后再另行决定。
  4. A：材料明确、结果结构清楚，可以逐项对照原记录。
  5. C：密码和验证码不得提供，转账也属于需要本人确认的重要动作。
  6. B：起草可以，群发不可以跳过本人对收件人、内容和影响范围的复核。

通过标准：第 3 题（无备份删除）、第 5 题（密码与验证码）和第 6 题（未经检查外发）必须答对，六题合计至少答对五题；此外，你任选的两题都必须分别写全「允许提供的材料、核验方法、必须由人确认的最后一步」，且三项与题目风险一致。只答对 A/B/C、没有完成两题三项说明，仍不算通过。如果写不出来，回到 2.4 的四个问题再判断一次。

本章小结

  • Codex 是 OpenAI 提供的 AI 智能体工具，尤其适合软件开发和技术任务，也能协助研究、文件和内容工作；本教程主要讲桌面应用入口。
  • 适合首先尝试的任务通常有材料可依、结果可查、出错后容易修改。功能是否可用，取决于平台、套餐、地区、设置、插件和权限。
  • 流畅不等于正确。重要事实查来源和日期，缺少的背景要补充，外部网页和插件数据要当作未经信任的输入。
  • 权限和审批行为由环境与模式共同决定。练习用专用文件夹，重要文件先备份，看不懂的请求先停下来问清影响。
  • 四问口诀：材料可提供，范围先限定；结果能核验，重要动作我确认。
