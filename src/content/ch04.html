第一次对话：把需求说清楚

4.1说清楚需求，比会用软件更重要

Codex 不会读心。它只能根据你写下的文字，理解你要什么。很多人第一次用时会觉得沮丧——不是因为软件难用，而是因为请求写得太模糊。

比如只发一句「帮我整理一下这个」。到底整理成什么样？保留什么、去掉什么？它只能猜——猜错了，你就要返工。

好消息是：把需求说清楚不需要任何技术背景，它更像是给一位新同事交代工作。你只需要回答四个问题。

4.2四要素：任务、范围、材料、期望

把一个请求拆开看，其实就是回答下面四个问题。

要素回答的问题写法建议
任务你要它做什么？用一句话、以动词开头：「整理……」「写一份……」「检查……」
范围允许它动什么、不许动什么？说明只处理哪些内容；需要保留原样的部分要点名。
材料它需要看什么才能干活？把相关文字粘贴进对话，或把文件拖进输入框；没有材料就直说「没有材料，请从零开始」。
期望你想要什么样的结果？说清格式（列表、表格、正文）、长度、语气，以及「怎样算完成」。

帮我弄一下产品介绍。

任务：帮我把下面这段产品介绍改写得更通顺。 范围：只改文字表达，不要增加或删除产品信息，价格数字保持原样。 材料：「蓝溪文具的樱花笔记本，A5，一本 18 元，纸很好写字不洇，封面有三种颜色卖得很好。」 期望：改成一段 80 字以内、适合放在商品页开头的介绍，语气亲切一点。

两种写法差在哪？对比一下：

  • 「帮我弄一下产品介绍」——任务、范围、材料、期望都没说，Codex 只能靠猜。
  • 上面的正面例子——四件事都说清楚了，Codex 不用猜任何一件事。

四要素不必写成表格，用平常说话的语气就行。关键是四件事都要提到。

4.3动手：发出你的第一个请求

下面用上面的虚构材料，实际走一遍。每一步都写了「你应该看到什么」，方便你确认自己没有走偏。

  1. 打开 ChatGPT 桌面应用，确认左上角是 Codex 视图。你应该看到窗口左上角写着 Codex（而不是 Chat 或 Work）。不是的话，点左上角菜单切换到 Codex（第 3 章 3.5）。
  2. 新建一个对话。如果它问你要在哪里工作（Local / Worktree / Cloud），这次什么都不选，直接开始——第一个练习只是文字改写，不需要它碰任何文件。你应该看到一个空白的输入框，光标可以点进去打字。
  3. 看一眼输入框下方的权限模式。应该显示 Ask for approval（先问我）。不是的话改回来，再继续。
  4. 把请求写进输入框。做完后你应该看到输入框中显示了你输入的文字。可以直接照抄上面的正面例子；想用自己的内容练习，也请先编一个虚构版本，不要粘贴真实的客户、公司或个人信息（第 1 章的底线，在这一步最容易被忘掉）。换行和发送用哪个键，界面上一般有提示；找不到就把请求写成一段发出去也没关系。
  5. 发送，等待回复。你应该看到 Codex 开始输出文字，有时它会先显示「正在思考」之类的过程；等它完全停下来再往下读，中途内容可能还会变化。这个练习不涉及文件和上网，所以不应该弹出任何审批框——如果弹了，先点拒绝，看看它想做什么。
  6. 把回复从头到尾读完。做完后你应该看到了 Codex 的完整回复，包括改写结果和可能的理解说明。记住不要只看开头。

预期结果：你会得到一段改写后的产品介绍，长度和语气大致符合你的要求。它可能和你想象的不完全一样——这是正常的，下一节教你怎么办。

4.4收到回复后：三步检查

  1. 它做了什么？用自己的话概括回复内容。如果你说不清它做了什么，先别用这个结果。
  2. 是不是你要的？对照你写的「期望」逐项核对：格式对吗？长度对吗？该保留的信息（比如价格「18 元」）还在吗？
  3. 有没有多做？检查它有没有超出「范围」——比如凭空加了你没提供的卖点。凡是材料里没有的信息，都要当作它的猜测来对待，不能直接采用。

不满意就直接说，像跟人对话一样提出修改：「第二句改回原来的说法」「再短一点，50 字以内」。每次只提一两个修改点，比重新发一大段需求更有效。

4.5常见毛病与修正

下面是几个常见的模糊写法，以及怎么修正。

毛病典型表现修正方法
任务太大「帮我把店铺运营做好」拆成能一次完成的小任务：先「写 3 条新品文案」，再逐步推进。
忘了说期望得到大段文字，其实你想要表格补一句：「用表格重新给我，列是名称、价格、卖点。」
一次塞多个任务「改写介绍、再做个价目表、顺便想十个店名」一次一个任务，做完检查完再下一个。
材料没给够它开始编造你没提供的细节指出「这些信息我没有提供，请删掉」，并补上真实材料或明确说「没有的信息留空」。

4.6什么时候必须停下来

遇到以下任意一种情况，先停止，不要继续发送：
  • 你正准备把真实的个人信息（身份证号、住址、他人隐私）粘贴进对话；
  • 你正准备粘贴账号密码、支付信息或公司要求保密的资料；
  • 它的建议涉及付费、删除文件、发送消息给别人等无法轻易撤销的操作，而你还没弄懂后果。

练习阶段一律使用虚构材料（就像本章的「蓝溪文具」）。真实材料要等你熟练之后，并且确认符合第 10 章的安全边界再使用。

本章小结

  • 请求 = 任务 + 范围 + 材料 + 期望，四件事都提到就是清楚的请求。
  • 回复要读完，并做三步检查：做了什么、是不是你要的、有没有多做。
  • 修改时一次提一两个点；材料里没有的信息一律当作猜测。
  • 涉及隐私、密码、钱和不可撤销的操作，先停下来。
