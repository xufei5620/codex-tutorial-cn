Codex 长期教程：框架总览

给第一次接触 AI 与 Codex 的中文读者：先建立清晰、可离线阅读、可持续维护的学习地图；每一课的正文随后按相同标准逐条补齐。

当前状态：框架优先。页面中已有的正文、示例和演示材料均是 seed/sample，用来验证信息架构和发布流程，不等同于最终课程。后续新增或替换任何课程时，必须使用下方模板、完成来源与验证记录，再进入发布状态。

这套教程服务谁，以及不服务什么

目标读者

刚接触 AI、Codex 或电脑操作的中文读者。用最少前置知识完成实际协作任务，并知道何时停止、检查和求助。

支持的平台

Windows 与 macOS。教程提供平台差异提示与验证记录；页面本身可在本地离线打开。

首版边界

不讲软件开发、CLI、IDE、API、SDK、Git 或 Linux。它们不是“默认前提”，未来如需加入会独立成扩展路线。

独立入口：行业提示词库 + 效果图

提示词按五个行业入口组织：通用办公、电商、餐饮与本地服务、内容与媒体、教育与培训。每个入口覆盖六类任务：调研整理、写作改写、方案规划、数据理解、视觉创意、复盘优化。首版结构预留 26 条唯一提示词与30 个展示位；效果图均使用自有或明确许可的虚构材料。

插件与 Skill：一项一目录

每个插件、每个 Skill 均在其主目录下以自身名称建立独立目录。目录中分别保存读者页、来源证据、许可与版本、权限/风险、验证记录和自有示例；不混放第三方资料，也不把外部项目直接改写为无来源内容。

内容从候选到发布

  1. 候选
  2. 来源复核
  3. 技术复核
  4. 读者试读
  5. 可发布
  6. 已发布
  7. 需复核 / 已撤回

高、中、低风险资料分别默认在 30、90、180 天复核。每一课都应写清目标、前提、步骤、预期结果、风险、验证方式、来源与复核日期。

GitHub、Notion 与公开边界

GitHub 和其他网站用于方法研究、来源比对与许可判断；引入内容前记录固定版本/提交、上游、许可、复制范围、风险与复核日期。Notion 是私有维护台账，用于候选、审核、排期、反馈与复核提醒；对外只发布经过受控投影的 HTML 内容，内部笔记和未验收材料不外泄。

若创建 GitHub 仓库，必须是公开仓库，并且仅在验收后创建。公开仓库只包含通过公开白名单的发布内容，不自动包含本地开发历史、内部审核或草稿。
