# 连接失败怎么排查

先停止重复重试和批量任务。保留错误码、脱敏文案、请求 ID、工具版本、模型和发生时间；不要公开完整配置与日志。

## 1. 工具能不能启动

先运行工具自己的版本查看命令。命令找不到、安装失败和客户端崩溃，不是同一类模型接口问题。确认终端是否重开、安装在哪个用户或环境里，再看 [Node.js 与终端](/clients/nodejs)。

## 2. 配置是否真正被读取

检查文件路径、扩展名和配置作用域。Windows 不要把 `.env` 存成 `.env.txt`；JSON 不允许多余逗号；同一 TOML 表不能重复定义。改动前先备份。

本机、WSL、容器和远程服务器可能各自拥有配置。终端中临时设置的环境变量，也不代表另一个图形应用已经读取到。

## 3. 地址与协议是否匹配

确认 Base URL 不是控制台或教程地址，也没有把完整请求路径重复填入基址。OpenAI Chat Completions、Responses、Anthropic Messages 和 Gemini 协议并不等价。带不带 `/v1` 按具体工具配置与实际服务要求确认，不采用统一口诀。

## 4. 认证与模型是否匹配

检查%%KEY_WORD%%是否完整、启用、有可用额度，以及所属分组是否允许目标模型或客户端。使用 [本站密钥页面](%%KEYS_URL%%)和 [模型列表](%%MODELS_URL%%)核对。

不要把官方账号密码、网页登录令牌、第三方平台密钥互相替代。收到客户端或渠道限制时使用允许的接入方式，不修改工具身份规避限制。

## 5. 按结果继续定位

| 现象 | 下一步 |
| --- | --- |
| 认证失败 | 检查密钥、环境变量来源和当前登录方式 |
| 模型不存在或不允许 | 核对精确模型 ID、分组与模型限制 |
| 路径不存在或协议错误 | 对照客户端教程，检查最终请求路径是否重复或缺失 |
| 额度不足或限流 | 检查余额、套餐、并发、频率和重试提示，停止高频重试 |
| 超时或服务错误 | 记录时间与请求 ID，检查公告，再做一次小请求验证 |
| 有回复但预期功能失败 | 单独验证该功能，不把聊天成功等同于完全兼容 |

各错误码的本站含义见 [错误码对照](/errors)，不要仅凭状态码猜测扣费或账号状态。

## 6. 联系客服时提供什么

通过 [本站客服](/contact)提交：工具与系统版本、模型 ID、发生时间和时区、脱敏报错、已经尝试的检查。只有涉及账户或订单时，再在确认的私密客服会话中提供必要信息。

不要发送 API Key、Authorization、Cookie、密码、验证码、未使用兑换码或完整聊天材料。怀疑泄露时先停用旧密钥，再生成新密钥并逐个更新使用位置。
