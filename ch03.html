安装、登录与界面

从官方入口安装 ChatGPT 桌面应用，用 ChatGPT 账号完成登录，进入 Codex，认清界面的主要区域，并把权限保持在适合初学者的安全边界。每一步都给出可观察结果、纠正方法和停止条件。

3.1开始前：你需要什么

需要现在怎么确认不符合时怎么办
一台 Windows 或 Mac 电脑打开官方下载安装页，确认页面为你的系统提供可选版本。课程目前不对 Windows 最低版本、macOS 最低版本或 Intel Mac 作未经验证的承诺。页面没有适合你设备的版本，或安装程序明确提示不兼容，就停止安装，不要去第三方网站找所谓“兼容版”。
一个 ChatGPT 账号，或创建账号的准备本章主路线使用 ChatGPT 账号登录。已有账号就准备好自己的登录方式；没有账号，可以等桌面应用安装完成后，从应用发起的官方浏览器流程查看是否提供创建入口。个人账号和单位工作空间看到的功能可能不同。单位设备或工作空间要求 SSO（单位统一登录）、邀请或管理员批准时，先向管理员确认。不要为了绕过限制临时注册或借用别人的账号。
稳定网络安装、登录和向模型发送请求都需要联网；本地文件操作和云端处理的边界还会受登录方式与权限设置影响，隐私底线见第 1 章。网络不稳定时先暂停，不要在登录按钮上反复点击，也不要把密码或验证码发给别人代登。
一个空的练习文件夹按下面的“创建并确认为空”步骤，新建一个没有私人资料的文件夹，例如“Codex-练习”。以后第一次允许 Codex 处理本机文件时，只选择这个文件夹。不要直接选择整个“桌面”“文档”“下载”、个人照片库或公司的共享盘。
正文学习约 25 分钟这是阅读、理解和完成检查的估计时间；下载、安装与登录耗时另计，网络和设备状态不同，实际时间也会不同。时间不够就停在当前步骤；不要为了赶进度选择 Full access 或忽略系统警告。

没有账号不影响你先完成官方下载与安装。等桌面应用正常打开后，从应用里的登录按钮启动浏览器流程；若页面提供创建账号，可按官方提示使用自己的邮箱或受支持的登录方式注册。单位设备或工作空间要求 SSO、邀请或管理员批准时，先联系管理员。本章不要求为注册而购买套餐，也不把 API Key 当作零基础替代路线。

创建并确认练习文件夹为空

  1. Windows：打开“文件资源管理器”，进入一个你自己拥有、专门用于练习且不含真实资料的位置；右键空白处选择“新建 → 文件夹”，命名为「Codex-练习」。
  2. macOS：打开 Finder，进入一个你自己拥有、专门用于练习且不含真实资料的位置；使用“文件 → 新建文件夹”或当前系统显示的同义操作，命名为「Codex-练习」。
  3. 两种系统都要检查：双击打开「Codex-练习」，确认里面没有文件或子文件夹，再记住它的完整位置。若同名文件夹已经存在，先打开核对；只有确认为空且专用于本教程时才复用，否则选择下一个未使用的名称，例如「Codex-练习-02」「Codex-练习-03」。把最终名称写在纸上或记事本里。后续章节为了简短统一写「Codex-练习」，实际操作时都要替换成你在这里记录的最终名称，不要再创建另一个文件夹。

开始前检查

  1. 看下载页。能看到与你的操作系统相符的下载入口。
  2. 看账号。已有账号时，知道自己将使用个人账号还是单位工作空间；没有账号时，知道要等应用安装完成后从官方登录流程查看创建入口。
  3. 看练习范围。已经亲自打开练习文件夹，确认其中没有文件、子文件夹或真实业务资料。

通过标准：三项都满足再继续。任何一项不确定，就先纠正，不把“不确定”当成“应该可以”。

产品、功能和套餐的地区可用性会变化。若官方页面或登录界面明确提示当前地区、账号或工作空间不支持，请停止，不使用代理、共享账号或其他方式绕开限制。本教程只讲官方支持范围内的正常使用。套餐能力和实时额度以官方定价与功能页以及账号内的用量页面为准。

3.2先弄清楚：现在的 Codex 在哪里

这一步只认准桌面应用中的 Codex。现在要下载的软件名称是 ChatGPT；安装并登录以后，再从应用里的产品或模式入口选择 Codex。本章后面的安装、界面和权限步骤都指这条桌面路线。

当前官方快速入门让用户从 ChatGPT 的下拉入口选择 Codex。菜单在窗口里的具体位置可能随版本变化，所以只认准文字 Codex，不把“左上角第几个按钮”当成固定规则。若下载页仍显示旧名称或图标，也以当前官方安装入口和应用内说明为准。

可观察结果：你能说出：“我要安装 ChatGPT 桌面应用，登录后选择 Codex。”做到这一点就可以继续，不需要先学习其他入口或开发术语。

可选补充：旧名称和其他 Codex 入口

2026 年 2 月，OpenAI 发布了独立 Codex 桌面应用；2026 年 7 月 9 日，Codex 并入 ChatGPT 桌面应用。这段变化可在官方更新记录中核对。下面这些入口都真实存在，但不是完成本章的前提。

入口在哪里运行本教程怎么安排
ChatGPT 桌面应用中的 Codex在你的 Windows 或 Mac 上运行本地任务，可使用你明确加入项目的文件夹。本章主路线。
Codex Cloud从网页入口连接 GitHub 或 GitLab，在隔离的云环境中运行任务。属于进阶路线，详见官方云端说明。
手机 RemoteChatGPT 手机应用可以连接一台在线的 Mac 或 Windows 主机，远程启动、指导、审批和审阅任务；工作仍在连接的电脑上运行。不是手机本地执行；可用性取决于推出范围与工作空间，见官方说明。
Codex CLI / IDE 扩展分别在终端或代码编辑器中使用。是不同学习路线，参考CLI与IDE 扩展文档。

3.3Windows 安装步骤

官方 Windows 专项说明见ChatGPT 桌面应用 for Windows。它提供 Microsoft 的官方下载入口；页面和按钮文案可能随 Windows、Microsoft Store 或安装器版本变化。

  1. 从官方页面开始。在浏览器地址栏手动输入 https://chatgpt.com/download/，确认使用 HTTPS，再选择 Windows。不要从广告、网盘、软件下载站或陌生邮件附件安装。
  2. 进入 Microsoft 安装流程。官方链接可能打开 Microsoft Store，也可能调用 Microsoft 的安装器。确认要安装的应用名称是 ChatGPT，然后使用页面实际显示的“获取”“安装”或同义按钮。
  3. 等安装完成。只处理正常的 Microsoft 安装提示。若系统要求管理员密码、关闭安全软件、修改执行策略或运行一段陌生命令，先取消并看本节的停止条件。
  4. 打开应用。从安装完成页点“打开”，或在开始菜单搜索“ChatGPT”。第一次打开时不要急着选择文件夹或更高权限。

可观察结果：开始菜单里能找到 ChatGPT；应用可以正常打开，并显示登录入口。达到这个结果后去 3.5。

检查、纠正与停止

  • 检查：浏览器起点是官方 HTTPS 下载页，后续安装来自该页面指向的 Microsoft 流程。
  • 纠正：若安装到一半失败，完整关闭安装器，重启 Windows，再从官方页重新开始；记录完整错误文字和出现时间。
  • 停止：第三方页面要求付费下载、输入 ChatGPT 密码、关闭安全软件或以管理员身份运行陌生脚本时，立即停止。

官方文档说明 Windows 桌面应用默认使用 Windows 原生 Codex 代理，在 PowerShell（Windows 自带的命令工具）中运行命令，并用 Windows 沙盒限制可接触的资源。初学者保持默认即可，不需要安装 WSL（在 Windows 中运行 Linux 的可选环境），也不要为了“让它更顺”而以管理员身份长期运行应用。沙盒的正式解释见 3.7。

3.4macOS 安装步骤

本章只跟随官方桌面应用页当前提供的 macOS 版本。由于真实设备验证尚未完成，这里不承诺 Intel Mac、固定 macOS 最低版本或一定存在某种安装包；下载页没有为你的设备提供版本时就停止。

  1. 先确认自己的设备。打开苹果菜单里的“关于本机”，记下芯片类型和 macOS 版本。此信息只用于和官方下载页、安装程序的兼容提示核对。
  2. 从官方页面下载。在浏览器地址栏手动输入 https://chatgpt.com/download/，选择页面为你的 Mac 提供的版本。不要根据第三方文章猜测 Intel 或 Apple 芯片版本。
  3. 按安装包实际提示安装。如果下载的是 .dmg，双击打开；若窗口要求把 ChatGPT 拖进 Applications（应用程序），照做。若官方安装包显示其他流程，以它的实际提示为准。
  4. 从“应用程序”打开 ChatGPT。macOS 可能显示正常的“从互联网下载，是否打开”确认。先核对应用是刚从官方入口下载的 ChatGPT，再确认打开。

可观察结果：“应用程序”中有 ChatGPT；应用可以正常打开，并显示登录入口。达到这个结果后去 3.5。

若 macOS 显示“身份不明的开发者”、无法验证开发者、安装包损坏，或官方下载页没有适合你设备的版本，不要绕过 Gatekeeper（macOS 的应用来源安全检查），也不要在终端移除隔离属性。删除该安装包，从官方入口重新下载；仍出现同样提示，就保存截图并按 3.8 求助。

本地命令的沙盒使用 macOS 自带的系统隔离机制（技术名 Seatbelt；现在不必记住）；访问“桌面”“下载”“音乐”等受保护文件夹时，macOS 还可能单独询问。以后若安装 Computer Use，又会涉及屏幕录制和辅助功能权限。这些权限彼此独立，不能因为允许了一个就默认全都允许。

3.5首次登录，切换到 Codex

官方支持使用 ChatGPT 账号或 API Key 登录本地 Codex。本章采用较容易理解的 ChatGPT 账号登录；完整差异见官方身份验证文档。

  1. 从应用启动登录。在未登录页面选择 Continue to sign in（继续登录）或意思相同的按钮。正常流程会打开默认浏览器。
  2. 在浏览器完成登录。优先使用刚才由应用自动打开的页面，不从搜索结果重新找登录页。使用邮箱密码时，核对 HTTPS 和完整主机名：chatgpt.com、openai.com，或以点号分隔的官方子域名才属于这两个域；fakeopenai.com、openai.com.example.net 和 chatgpt.com.example.net 都不是。选择 Google、Microsoft、Apple 或单位 SSO 后可能进入相应身份提供方；只在你刚选择的正式登录流程中继续，不确定域名就关闭页面，从桌面应用重新发起。
  3. 正确处理其他登录方式。若你主动选择 Google、Microsoft、Apple 或单位 SSO，浏览器进入相应身份提供方的正式域名属于正常流程。没有主动选择却被带到陌生网站，就关闭页面。
  4. 回到桌面应用。登录成功后，浏览器可能询问是否打开 ChatGPT。确认请求来自刚完成的官方登录流程，再返回应用。
  5. 核对身份。在个人资料或账号菜单确认当前账号和工作空间。单位工作空间里看不到某项功能，不一定是安装失败，也可能是套餐、角色或管理员策略造成的。
  6. 选择 Codex。从应用里的 ChatGPT 产品下拉菜单或当前版本提供的模式入口选择 Codex。不要依赖固定方位，只认准名称。
  7. 先看权限再发送。找到输入框附近的权限选择器，确认显示 Ask for approval。如果找不到，先读后面的3.6找到权限位置，再读3.7了解边界，然后回到本步骤；仍找不到就按 3.8 排查。此时先不发送任务，也不选择 Full access。

可观察结果：应用显示正确账号和工作空间；当前产品为 Codex；能看到 New chat（新建对话）或输入框；权限为 Ask for approval。

Sign in another way（用其他方式登录）可以进入 API Key 登录，这不是故障入口。API Key 使用量按 OpenAI API 价格另行计费，不使用 ChatGPT 套餐内含额度，而且部分依赖 ChatGPT 工作空间或云服务的功能可能不可用。初学者没有明确的 API 计费需求就不要选择；任何情况下都不要把 API Key 粘贴进普通对话。

纠正和停止条件

  • 登录后回不到应用：关闭重复打开的登录页，只保留一次由应用发起的流程；仍失败就记录浏览器和应用显示的完整错误。
  • 看不到 Codex：先确认账号、工作空间、登录方式和应用版本，再按 3.8 排查，不要反复卸载。
  • 网页、聊天框、远程协助者或陌生弹窗索要密码、验证码、恢复码或 API Key：立即停止，不输入、不发送。

3.6界面导览：认识五个区域

下面的“五个区域”是为了帮助你认路，不是对每个版本像素级不变的承诺。侧栏项目、名称和位置会随套餐、工作空间、功能开关与版本变化。

区域常见位置你现在只需知道
导航与侧栏窗口左侧常见内容有 Chats（对话）、Projects（项目）以及在账号可用时出现的 Scheduled、Activity 等。Projects 既可能是 ChatGPT 项目，也可能连接一个或多个本机文件夹；不要把“项目”简单等同于任意文件夹。
输入框（composer）窗口中下方输入请求、添加材料和发送消息。发送前先看清当前项目、目标和权限；不要把密码、验证码或密钥当材料上传。
模型与权限控制输入框附近模型决定使用哪种模型，可用项取决于账号和工作空间；新手保持推荐默认值。权限决定本地动作的边界，本章固定使用 Ask for approval。
对话与审阅区窗口中间和可展开面板对话区显示过程与结果。若项目是 Git 仓库，还可能出现 review pane（审阅面板）；它可能包含原来就存在的改动，不应全部归因于 Codex。零基础阶段先不要操作其中的技术按钮，回退边界见第 5 章 5.4。
Settings（设置）应用菜单；位置以当前版本为准官方快捷键是 macOS 的 Cmd+,、Windows 的 Ctrl+,。常见分类包括 General、Notifications、Appearance、Browser、Computer Use、Personalization、Memories 和 Archived chats；实际可见项可能不同。
可选补充：Git 审阅面板里的英文

以后使用 Git 项目时，面板可能显示 Unstaged、Staged、Branch、Commit 或 Last turn，并提供暂存、取消暂存和回退操作。这些都不是完成本章的前提；没学过 Git 时，只需记住“面板可能同时显示你、Codex 和其他工具留下的改动”，不要使用 Revert all。

后面章节会专门介绍 Plugins（插件，第 6 章）和 Skills（技能，第 7 章）。当前 Codex 界面可能在输入特定前缀时给出技能或插件建议；到对应章节再按你的实际界面操作。

判断一：这次对话要不要加入项目

项目用于组织一组相关对话、文件和说明；“是否加入项目”回答的是这次对话要不要共享这些上下文，还没有决定任务在本机还是云端运行。

判断含义初学者怎么选
不加入项目适合一次性的自包含问题，不自动获得某个项目共享的文件、说明和相关对话上下文。只问独立问题、也不需要项目材料时可以用。
加入或创建项目让相关对话在同一个项目下组织，并使用你为该项目明确提供的文件夹、文件或说明。第 4 章会加入练习项目，并先只提供空的「Codex-练习」文件夹；第 5 章继续在这个专用项目中使用虚构材料。

判断二：这次 Codex 对话在哪里运行

完成第一个判断后，再选择 Codex 对话的运行位置。Local、Worktree、Cloud 回答的是运行与文件隔离方式，不能拿来代替“是否加入项目”的判断。

运行位置含义初学者怎么选
Local在本机项目或指定文件夹范围内工作。需要练习文件操作时，只选 3.1 新建的空练习文件夹。
Worktree在 Git 仓库的隔离工作副本中工作。本章不选；到具备 Git 基础后再学。
Cloud在云环境运行，通常需要连接 GitHub 或 GitLab 并配置环境。本章不选；它不是“把本机文件自动搬到云端”的按钮。

基础路线的连续选择：第 4 章先加入练习项目，再为其中的 Codex 对话选择 Local，并且只打开空的「Codex-练习」文件夹。不要因为看到 Local 就以为已经选对项目，也不要因为加入了项目就假定它一定在本机运行。

30 秒界面检查

  1. 指出侧栏、输入框、模型控制、权限控制和设置入口。
  2. 先回答“是否加入项目”，再单独回答“这次 Codex 对话在哪里运行”。
  3. 确认当前没有误选真实工作文件夹、Worktree 或 Cloud。
  4. 确认权限显示 Ask for approval。

通过标准：四项都能确认，而且不会把“项目”和“运行位置”混成同一个选择。找不到某个区域时先查项目与对话、运行环境、设置或审阅面板的当前官方说明，不凭旧截图猜位置。

3.7权限模式：先弄懂再动手

权限不是一个简单的“能 / 不能”开关。沙盒规定 Codex 在不打断你的情况下能接触哪些文件和网络资源；审批规定它要越过边界时由谁决定是否继续。两者必须一起看，详见官方权限模式与沙盒说明。

模式实际边界本课程规则
Ask for approval
（请求审批）		官方推荐的大多数任务起点。Codex 可以在当前工作区读写并运行常规本地命令；使用命令访问网络或越出工作区边界时会暂停请求审批。具体行为还受本机配置和单位策略限制。本章和后续初学者练习都用它。
Approve for me
（替我审批）		与 Ask for approval 保持相同沙盒边界，但把符合条件的越界请求交给自动审阅。审阅可能批准、拒绝、中止或超时，并可能显示风险等级；自动审阅还会使用额外模型调用。初学阶段不用。它通常要在 Settings > General 的 Permissions 中启用，也可能被单位策略禁用。
Full access
（完全访问）		移除 Codex 的本地沙盒限制并关闭审批，显著扩大文件和网络风险。它仍受操作系统账号权限、管理员策略以及 Browser、Computer Use、插件等各自控制约束，但这不等于安全。不要用于本教程练习。看到警告就取消并切回 Ask for approval。

看到审批弹窗时，按四步判断

  1. 看动作。它到底要运行什么命令、打开什么网站、读写哪个路径或调用哪个外部工具？
  2. 对目标。这个动作是不是你刚才明确要求的？目标是不是练习文件夹或你认可的网站、账号？
  3. 选最小范围。若确实需要，在弹窗实际提供的选项中选择能继续任务的最小授权，例如只允许这一次。不同类型的审批不一定都有“本次对话”或持久允许选项。
  4. 不懂就拒绝。拒绝会阻止当前被拦截的动作继续，但不会自动撤销 Codex 在此之前已经完成的工作区内修改，所以拒绝后仍要检查文件变化。
  • 开始任务前确认 Ask for approval，不要假设它永远自动保持。
  • 本机文件练习只使用专门新建的练习文件夹，不选择整个桌面、文档、下载或个人主目录。
  • 审批中出现删除、覆盖、清空、发送、发布、支付、登录、密钥或扩大目录范围，而这些不在你的明确要求里，就先拒绝并停止任务。

别把四种权限混在一起

  • Codex 沙盒与审批：控制本地文件、命令和命令网络访问。
  • 操作系统权限：macOS 访问桌面、下载、音乐等目录时可能另行询问；Windows 的访问失败或系统提示要按 Windows 自身规则处理，不能照搬 Mac 步骤。
  • Browser / Computer Use / 插件权限：可能另有网站、应用、账号和有副作用动作的审批；允许本地文件夹不等于允许这些工具。
  • 单位管理员策略：可能隐藏或禁用某种模式，也可能限制账号、模型和工具；个人设置不能绕过它。

本节验收

不要为了测试而故意访问私人目录。只需确认权限选择器为 Ask for approval，并能回答：“工作区内的常规动作可能直接执行；越界请求应暂停；拒绝只阻止当前请求，我仍要检查此前变化。”答不出来就回看本节，暂不进入第一次文件任务。

3.8装不上、登不进怎么办

排错不要靠连续乱点。先记录操作系统与版本、设备芯片、ChatGPT 应用版本、账号/工作空间、登录方式、完整错误文字和出现时间，再从与你的现象最接近的一行开始。

现象检查与纠正停止条件
下载页打不开、很慢或没有适配版本确认完整地址是 https://chatgpt.com/download/；换一个正常网络后重试一次。没有适配版本时记录系统和芯片信息。不要改用第三方镜像、网盘安装包或所谓绿色版。
Windows 安装失败关闭安装器，重启电脑，从官方下载页重新进入 Microsoft 安装流程；保存错误代码。若只是安装问题，不需要先修改 PowerShell 执行策略。要求关闭安全软件、运行陌生脚本、长期以管理员身份启动应用，或单位电脑需要管理员授权时先停止。
macOS 显示开发者无法验证、身份不明或安装包损坏删除安装包，从官方下载页重新下载一次，并核对设备是否有适配版本。不要绕过 Gatekeeper，不运行解除隔离、跳过签名验证的命令。
浏览器登录完成，却没有回到应用确认流程由桌面应用发起；只保留一个登录页面，关闭重复页面后再试一次。记录浏览器与应用两边的完整提示。不要把登录后用于返回应用的链接（回调链接）、验证码、密码、恢复码或 API Key 发给远程协助者。
已登录，但找不到 Codex确认当前账号、工作空间、登录方式和应用版本；完整退出应用后重新打开。单位账号请让管理员确认 Codex、模型和本地客户端权限。不要把切换账号、借用账号或改用 API Key 当成绕过单位策略的方法。
提示达到用量上限这通常不是安装故障。打开账号内的 Codex usage 页面查看剩余额度和重置时间；限制会随套餐、模型和任务变化，周限制也可能适用。不要相信第三方“解除限额”工具，也不要在不理解 API 计费时临时改用 API Key。
对话看起来卡住先看 Codex 是否正在等待审批；有待审批项就读清后拒绝。若回复仍在运行，使用当前界面中与该回复直接相连、含义明确的停止或取消控件；确认内容不再追加、界面不再显示该轮仍在运行后，再用更短、更明确的请求新建对话。看不懂控件或无法确认已经停止时，保持不审批并求助，不要靠继续发消息测试。不要因卡住就切到 Full access，也不要在不清楚状态时反复提交同一个有副作用的请求。

求助时一次说清楚

  1. 按第 10 章 10.5整理复现步骤，同时附上系统、芯片、应用版本、账号/工作空间类型和准确时间。
  2. 先查官方桌面应用排错页；在应用输入框输入 / 时，若当前版本提供反馈入口，可按提示提交并保存会话 ID。
  3. 需要联系官方支持时，从官方文档或应用内帮助入口进入，不点击搜索广告中的“客服”。
  4. 分享截图、会话或日志前，遮住邮箱、姓名、单位、文件路径、项目名，并删除登录凭据（例如令牌和 Cookie）、验证码、API Key 和真实业务内容。

通过标准：你能保留原始错误文字，完成一次有顺序的排查，并在遇到安全或系统边界时停下来。排错目标是找到原因，不是“不惜代价让它运行”。

本章小结

  • 本章主路线只要求认准 ChatGPT 桌面应用中的 Codex；其他入口与开发术语不是基础路线的前提。
  • 只从官方 HTTPS 下载入口开始；页面没有适配版本或系统出现高风险安全警告时就停止，不找第三方安装包、不绕过 Gatekeeper。
  • 登录由应用发起；核对完整域名和身份提供方，绝不在对话或陌生弹窗中提交密码、验证码和 API Key。
  • 界面可用五个区域认路，但具体名称与位置会变化；Git 审阅面板显示的也不一定全是 Codex 做的修改。
  • 初学者使用 Ask for approval。沙盒、审批、操作系统权限以及 Browser、Computer Use、插件权限是不同层次。
  • 拒绝越界请求会阻止该动作继续，但不会自动撤销此前修改；排错和审批之后都要检查已经发生的变化。
离章 go / no-go

下面五项全部回答“是”才进入第 4 章：① ChatGPT 来自官方入口并能正常打开；② 你知道当前账号和工作空间；③ 当前产品显示 Codex；④ 第 3 章准备的空「Codex-练习」文件夹仍能找到；⑤ 权限显示 Ask for approval。任一项为“否”或“不确定”，就停在本章按 3.8 排查，不用 Full access 绕过。
