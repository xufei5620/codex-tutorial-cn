第 5 章 草稿

日常协作：检查、修改与回退

  • 预计阅读 4 分钟
  • 适用平台：Windows / macOS
  • 前提：读过第 4 章，能发出一个四要素齐全的请求
本章目标

第 4 章教你发出第一个请求；这一章教你把这件事变成可靠的日常习惯——每次都检查、有效地提修改、永远留退路。

5.1为什么不能照单全收

第 2 章说过一个道理：Codex 有时会一本正经地编造内容，也完全不知道你没告诉它的事。所以最危险的用法，就是「它写什么，你就直接用什么」。

正确的做法是一个循环：你交代 → 它产出 → 你检查 → 你决定。检查完，你有三种选择：采用、让它改、或者放弃重来。

检查这一步永远不能省。通知发出去、报告交上去，署名的是你，不是 Codex。「是 AI 写错的」不是能拿来解释的理由。

5.2核对事实：把内容分成三类

检查一段输出时，先把里面的信息分成三类，再分别处理。

类别怎么识别怎么处理
材料里有的能在你提供的文字里找到出处对一遍有没有抄错、改错，数字和名字要重点看
合理推断的材料里没直说，但顺理成章，比如把「下周三」换算成具体日期确认推断用的前提对不对
凭空出现的材料里完全没提到的名字、数字、说法、出处一律当作编造处理：要么删掉，要么自己核实后再用

你给了蓝溪文具三款笔记本的价格，让 Codex 写一段促销文案。输出里出现了「全场第四件半价」——你根本没提过这个活动。这就属于「凭空出现的」，要立刻指出：「我没有提供这个活动，请删掉。」

5.3有效的修改请求

结果不满意时，别只说「不好，重写」。它不知道哪里不好，重写往往更糟。有效的修改请求有三个特征。

  • 具体：指着改。「第二段太啰嗦，压缩到两句」好过「简洁一点」。
  • 少量：一次提一两个点。改完检查，再提下一个。一口气提八个要求，经常顾此失彼。
  • 可核对：提的要求你自己能验证。「控制在 100 字以内」「保留所有价格数字」都是发回来一眼能查的。
  • 「感觉不太对，你再弄弄。」它不知道哪里不对，只能瞎猜，越猜越偏。
  • 「两处修改：① 开头别用『亲爱的顾客』，直接说事；② 最后加一句退换货提醒，用材料里原来的说法。」——具体到句子，一次只改两处。

如果改了三四轮反而越改越乱，别硬撑。把目前最好的一版复制出来，开一个新对话，带着这个版本和明确的要求重新开始（做法见 5.5）。

5.4保留退路

养成下面三个习惯，不管出什么问题，你都有后悔药可吃。

  1. 动文件前先复制一份。让 Codex 处理某个文件之前，自己先复制一份原件放在一边。这是最朴素、也最可靠的保险。
  2. 要新文件，不要覆盖。交代任务时说清楚：「结果放在新文件里，不要改动原文件。」这样原件永远保持干净。
  3. 版本留名。重要的内容多留几个版本，文件名里带上日期或序号，比如「促销文案-0901-第2版」。乱了随时能退回上一版。

Codex 自带的两道保险

除了上面三个靠自己的习惯，Codex 本身还有两样东西帮你留退路：

  • 沙盒：它只能碰你指定的那个文件夹。新建对话时选了 Local 并挑了一个文件夹，Codex 默认就只能读写那个文件夹里的东西，想碰外面的会先问你（第 3 章 3.7）。所以练习时永远新建一个专用文件夹，把要处理的文件复制进去，再把这个文件夹交给它——原件留在外面，它碰不到。
  • 审阅面板：改了什么，一行行给你看。它修改文件后，对话旁边会出现审阅面板（review panel），一般用颜色区分删掉的和加上的内容，并提供撤销（revert）。看到它改了你没让它改的地方，先在面板里撤销那一处（撤销能力的边界见下方说明）。

审阅面板的「撤销」在有的情况下并不完整（官方文档主要针对程序员用的 Git 项目描述了撤销能力，普通文件夹的一键撤销没有明确说明）。所以「动文件前先复制一份」这个习惯不能因为有审阅面板就省掉——它是最后一道保险，不是第一道。

停止条件：如果 Codex 的建议涉及删除、覆盖、清空任何你没有备份的内容，先点拒绝。审批弹窗里出现「删除」「delete」「remove」字样，也先拒绝。做完备份再继续。没有备份的删除，没有后悔药。

5.5对话的节奏：什么时候继续，什么时候重开

  • 继续当前对话：还在同一个任务上打磨——改措辞、调格式、补内容。上下文都在，越聊越顺手。
  • 开一个新对话：遇到下面任意一种情况：换了一件不相干的事；同一任务改了很多轮，它又把前面否定过的东西翻出来；对话太长，它开始「忘事」。重开时把最新版本和关键要求一起带过去，别指望它记得旧对话。

侧栏的 Chats 里能找回以前的对话，顶部有搜索框。做完的对话可以归档（archive），归档的在 Settings 的 Archived Chats 里还能找回来。

5.6「记忆」功能：让它记住你，还是不记

上一节说「别指望它记得旧对话」。不过 Codex 有一个可选的记忆（Memories）功能。打开后，它会把你的偏好（比如「这个人喜欢表格、不喜欢客套话」）记下来，以后的对话里自动用上。这个功能默认是关闭的，开关在 Settings → Personalization → Enable memories。部分地区暂不提供。

零基础阶段建议先不开，理由有两条：一是你还在练「把需求说清楚」，让它替你记反而练不出来；二是记忆存的是关于你的信息，多一个存放的地方就多一分要管理的东西。等你用熟了、清楚自己想让它记住什么，再开也不迟。开了以后，Settings 里的 Memories 页能查看和管理它记下的内容。

本章小结

  • 固定循环：你交代 → 它产出 → 你检查 → 你决定。检查这一步永远不能省。
  • 三分法核对：材料里有的对一遍，推断的验前提，凭空出现的一律当编造。
  • 修改请求要具体、少量、可核对；越改越乱就带最新版重开一个对话。
  • 三个退路习惯：动文件前先备份、要新文件不覆盖、版本留名。加上 Codex 的两道保险：只给它专用文件夹（沙盒）、改动在审阅面板逐处看、逐处撤销。没有备份不要删除。
  • 「记忆」默认关闭，零基础阶段先不开；开了以后记得定期看它记了什么。
